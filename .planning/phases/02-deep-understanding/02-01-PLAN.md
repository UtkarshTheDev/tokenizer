# Key concepts from research:

## BPE (Your current implementation)
- Merges most frequent adjacent pair
- Used by: GPT-2/3/4, Llama, Mistral
- Simple, greedy approach

## WordPiece  
- Merges pair that maximizes likelihood (language model score)
- Used by: BERT, Electra
- Better for understanding tasks

## Unigram
- Starts large, removes unlikely tokens
- Used by: T5, ALBERT
- Reverse approach from BPE

## SentencePiece
- Framework, not algorithm
- Treats whitespace as character
- Language-agnostic
</context>

    Create Unigram implementation in src/tokenizers/unigram.ts:

    1. Create `train(text: string, vocabSize: number)` function:
       - First pre-tokenize on whitespace
       - Start with initial vocab (all characters + common bigrams)
       - Loop:
         - Compute loss (log likelihood) for each token
         - Calculate importance: reduction in loss if token removed
         - Remove tokens with lowest importance until vocabSize reached
       - Return: { vocab: string[], tokenToId: Map }

    2. Create `encode(text: string, vocab: Vocab)` function:
       - Use Viterbi algorithm for optimal segmentation
       - For each position, compute best segmentation
       - Return token IDs

    3. Create `decode(tokens: number[], vocab: Vocab)` function:
       - Join tokens back to text

    Key difference from BPE: We REMOVE tokens, not add merges!
